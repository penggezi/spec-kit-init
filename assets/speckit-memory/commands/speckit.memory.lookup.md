# 经验库查阅

在开始规划 / 实现之前，把项目经验库中与当前功能相关的条目捞出来，供后续方案、任务或实现显式引用——避免"踩过的坑反复踩"。

## 相关性判据

取当前正在进行的上下文作为相关性判据（按可用程度优先级取）：

1. 本次实现的 spec 范围（`specs/<feature>/spec.md` 中描述的 WHAT / 边界 / 非目标）
2. 本次实现的 plan / tasks（`plan.md` / `tasks.md` 中的模块、技术点、涉及文件）
3. `$ARGUMENTS`（若由用户手动调用携带范围描述）

## 执行步骤

1. **读索引**：读取 `.specify/memory/lessons-index.md`（极轻量索引，每行 `YYYY-MM-DD · 根因关键词 · 简述`），扫描是否有与当前功能相关的**根因关键词**（同类技术、同类架构、已知坑位）。
2. **命中则读正文**：对命中的索引行，读取 `.specify/memory/lessons.md` 中对应条目正文，输出其中的「参考源 / 实际上 / 教训 / 适用范围」，供后续方案或实现显式引用。
3. **无命中则继续**：明确说明「经验库暂无本功能相关经验」，然后继续后续流程——**不要**为了"显得严谨"而硬编相关条目。

## 边界处理

- `.specify/memory/lessons.md` 或 `lessons-index.md` **不存在**（全新项目、尚未有复盘）→ 静默跳过，不报错、不打扰。
- 索引命中但正文条目缺失（索引悬空）→ 仅提示该索引行悬空，不阻塞。
- 这是**只读查阅**命令：不写入、不修改 `lessons.md` / `lessons-index.md`（写入由 `/retro` 负责）。

## 输出格式

```
## 经验库命中（与当前功能相关）

- {标题}
  - 参考源: {文件/URL/skill 名}
  - 教训: {一句话行动指引}
  - 适用范围: {何时应想起这条}
```

无命中时输出一行「经验库暂无本功能相关经验」。输出保持精简，只保留与当前功能真正相关的条目。
